# Локальный запуск ARGUS

Из папки argus-cashdesk запустите `./start-local.ps1` в PowerShell, затем откройте http://127.0.0.1:8000. Оставьте окно сервера открытым. Сайт автоматически подключается к этому серверу; вводить ключ вручную не нужно. На GitHub Pages сервер автоматически не подключается: там настройки задаются отдельно.

Первичная установка: `./setup-local.ps1` (Python 3.12+, Node.js 18+ и интернет для скачивания зависимостей). Видеозаписи и кадры не передаются облачным ИИ. Ollama запускается на 127.0.0.1:11434 с отключённым облаком.

На этом компьютере веса хранятся в D:\ArgusLocalModels, путь записан в .runtime/model-path. Runtime и ключ — в .runtime, исключены из Git. При переносе на другой компьютер запустите установку заново. Ollama остаётся работающим после остановки API; завершить его можно через диспетчер задач.

## Как работает проверка

Загрузите видео в рабочей области. Браузер отправит файл серверу, получит номер задания и будет опрашивать результат. Один GPU/CPU worker запускает неизменённый detector/submission.py из forte_final_submission.zip: qwen3.5:4b, context 4096, focused revision v06, thinking disabled. Параллельная отправка отклоняется кодом 429; интерфейс сам обрабатывает свою очередь последовательно. После принятия задания сервер ограничивает анализ 280 секундами, включая формирование ответа. Ошибка/тайм-аут означают failed, а не отсутствие нарушений. Точный процент распознавания модель не сообщает.

Для результата с событиями показываются таймкод, 1–3 JPEG кадра, описание и правовой контекст из переданного legal_catalog.json. Это основания для проверки сотрудником. Режимы detect/review_only и исходные промпты не изменены; юридический каталог не используется для изменения решения модели.

POST /api/v1/analyze, GET /api/v1/jobs/{job_id} и GET /api/v1/health требуют X-API-Key. Ключ генерируется локально в .runtime/api-key; можно переопределить ARGUS_API_KEY. GET /api/local-config.js передаёт его только браузеру на локальном компьютере. Сервис должен оставаться привязанным к 127.0.0.1. Готовность проверяется через /health; доступность модели проверяется перед приёмом видео. Падение сервера прерывает задания: они хранятся в памяти. Видеофайлы удаляются после обработки, история интерфейса хранится в браузере. Из-за декодирования браузер может не проигрывать некоторые MOV, но сервер всё равно может прочитать их через OpenCV.

## Проверки

124 теста из архива прошли; 8 интеграционных API-тестов прошли. Последние используют подменённый детектор для проверки контрактов, очереди, ошибок, авторизации и защиты локального ключа; это не измерение распознавания. Фронтенд собирается через npm run build. Тесты на Windows нужно запускать с доступной папкой TEMP и без ограничений локальной сети.

Команды из корня проекта: `$env:PYTHONPATH="$PWD\.runtime\python"`, затем `python -m unittest discover -s backend -p test_integration.py`. Для тестов детектора задайте TEMP/TMP внутри .runtime/tmp и выполните `python -m unittest discover -s backend/model_package/detector`.

## Ограничения

В архиве нет весов и видео. На этом компьютере обнаружен CPU и Intel UHD; ускоритель NVIDIA не обнаружен. Время до пяти минут на этом оборудовании не подтверждено. Из HANDOFF: известны пропуски X-1 и X-2, общая точность не заявлена. Статус done/no_violation не гарантирует отсутствия нарушений. Проверки на реальных Х-20.mov и Х-3.mov на этом CPU завершились failed: детектор не успел завершить обязательные проверки. Успешный полный анализ в пределах 280 секунд на этом ноутбуке пока не подтверждён.
